== Reproduire localement

Le TCK s'exécute via un script dédié à la racine du dépôt :

[source,bash]
----
cd knock
sdk env

# Test de fumée (KnockTckSmokeTest uniquement)
./run-official-tck-mp-health-4.0.sh

# Suite officielle complète (28 tests)
./run-official-tck-mp-health-4.0.sh all

# Un seul test par nom
./run-official-tck-mp-health-4.0.sh -Dtest=TestName
----

Le runner peut aussi être invoqué directement via le réacteur :

[source,bash]
----
./mvnw -Ptck -pl knock-tck test                  # smoke
./mvnw -Ptck,tck-official -pl knock-tck test     # suite officielle complète
----

[NOTE]
====
Le TCK s'exécute sur le classpath (et non le module path), contournement Java Modules délibéré pour Arquillian/ShrinkWrap. Depuis le 2026-07-15, `knock-tck` est dans le réacteur mais gardé derrière le profil Maven `tck` (même motif que les runners `vidocq-runtime-tck-*`) : un build ordinaire ne construit ni ne télécharge le harnais TCK. La contrainte historique ShrinkWrap Maven Resolver 3.3 vs Model 4.1.0, qui maintenait autrefois le runner hors du réacteur, est obsolète depuis la migration Maven 3.9.16 / Model 4.0.0.
====
